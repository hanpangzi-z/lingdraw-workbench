# 重新导入：暂存、确认与自动备份

## 行为

- 云端项目点击“重新导入”时，先等待已有自动保存完成并保存最新编辑；离线、冲突、保存失败时不离开原稿。
- 新资料在 `/projects/[projectId]/reimport` 暂存，该页面不挂载云端自动保存 Provider，也不允许用演示数据跳过确认。
- 用户可取消重新导入并返回原项目；退出后，迟到的解析、字段匹配和 AI 结果不能回写原项目。
- 数据确认页显示“确认替换原项目”，确认对话框展示原商品数、新商品数以及页面将重新生成的说明。
- 确认后上传所需资料，再调用专用重新导入接口。在同一数据库事务中创建“重新导入前自动备份”并替换数据；任一步失败均回滚。
- 空数据不能替换原项目；旧修订号返回冲突，不覆盖其他会话的新编辑。
- 网络中断导致结果未知时，保留同一请求重试；请求 ID 与备份绑定，不重复替换、不重复创建备份。
- 可以在版本历史中恢复替换前的商品、品牌配置和页面编辑。

暂存区目前是会话内暂存，不是持久草稿。刷新／退出会提示离开；取消不会改变已保存的原项目。确认过程中已上传的源文件可能保留在项目文件区，即使最终替换失败；原有文件不会删除。

## 验证

- `npm test -- --run`：198 项通过，含 11 项新增的事务调用顺序、空数据拒绝、冲突、幂等与取消后异步结果隔离测试。
- `npm run typecheck`：通过。
- `npm run build`：通过，新页面与 API 路由均已构建。
- `scripts/test-reimport-integration.ts`：在本地 PostgreSQL 的独立测试账号／项目执行，验证真实事务的备份失败回滚、替换失败回滚、空数据拒绝、成功替换、重复提交、修订冲突及完整恢复；测试数据已清理。需提供 `PPT_DATABASE_URL` 与本地素材存储环境后运行 `npx tsx scripts/test-reimport-integration.ts`。

本次浏览器验证受阻：`http://127.0.0.1:3000/ppt/projects` 显示“PPT 服务暂时不可用”，PPT 服务端口未监听。未修改运行环境中的认证配置，也未在真实用户项目触发替换。

## 服务恢复后的界面验收

使用独立测试项目：编辑一页 → 重新导入 → 取消 → 确认原数据保留；重新导入有效资料 → 数据确认 → 取消确认弹窗 → 应仍留在确认页；再次确认 → 查看新商品和“重新导入前自动备份” → 恢复备份。再验证解析中退出、保存失败、重复点击、网络中断重试及跨模块返回暂存页。
